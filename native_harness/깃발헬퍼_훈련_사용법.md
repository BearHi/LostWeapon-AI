# 깃발 헬퍼 로컬 훈련

## 훈1~20 시작

`깃발헬퍼_훈련.bat`을 더블클릭한다. 훈1~20과 중간 번호 **훈6.5·7.5·8.5**까지 총 23개 맵을 순서대로 실행한다. 기본은 맵당 총 20에피소드, 에피소드당 최대 500결정이다. 기존 훈1 100에피소드는 보존하고 다시 돌리지 않는다.

CMD에는 현재 맵 번호, 기존/새 에피소드 수, 에피소드별 깃발 성공과 결정 수가 보인다. 훈1에서 익힌 상황별 행동값을 훈2에 전달하고, 이후 맵에도 계속 넘긴다. **맵별 체크포인트와 성적은 따로 저장**해서 어느 지형에서 실패했는지 볼 수 있다.

기록된 **시작 지역 복귀 없는 최단 성공 행동열**을 다음 실행 첫 에피소드에서 원본 x86으로 다시 재생한다. 이후에는 그 행동열의 일부를 바꾸고 현재 물리 상태에서 다시 판단한다. 더 빠르고 복귀 없는 성공이면 추가 보상을 주고 최단 기록을 갱신한다. 예전 `physics_route_library.json`의 후보가 더 빠르면 먼저 재생해 검증한다. 훈5(127결정), 훈6(65결정), 훈12(122결정)의 예전 후보는 현재 오프라인 native 환경에서 각각 목표 영역 도달을 확인했다. 이는 일반 Client 화면에서의 검증은 아니다.

`깃발헬퍼_중지.bat`을 실행하면 현재 native 결정 뒤 기록을 저장하고 멈춘다. 다시 시작할 때 `깃발헬퍼_재개.bat`을 실행한다. 완료한 맵은 건너뛰고 미완료 맵에서 이어간다. 기존 공용 DQN·전투 체크포인트는 교체하지 않는다.

## 결과와 다음 단계

- 상태 파일: `checkpoints/route_curriculum/hun_status.json`
- 맵별 행동값: `checkpoints/route_curriculum/훈N.json`
- 맵별 행동 기록: `checkpoints/route_curriculum/훈N.episodes.jsonl`
- 복귀 없는 성공에서 추출한 발판 전이 조각: `checkpoints/route_curriculum/physics_transitions.json` (저장 단계이며 일반화된 자동 사용은 별도 검증 필요)
- 사용자가 이미 만든 훈1 기록: `checkpoints/route_rule_helper.json` 및 `.episodes.jsonl` (그대로 사용)

마지막 5에피소드에서 맵마다 깃발 성공률 80% 이상이면 `ready`로 표시한다. 이 기준은 **훈련 기록 기준**이며 보지 않은 맵에서의 일반화 증명이 아니다. `깃발헬퍼_혼련용.bat`은 훈 단계가 이 기준을 통과했을 때만 혼1~20과 중간 번호 맵을 시작한다. 혼 단계는 자동으로 시작하지 않는다.

기준 미달 맵에만 맵당 20에피소드를 추가하려면 CMD에서 다음을 실행한다. 반복은 한 번의 유한한 블록으로 끝난다.

```bat
cd /d "C:\Users\microsoft\Desktop\로스트웨폰 맵\native_harness"
python -u train_route_curriculum.py --stage hun --retry-failed
```

다른 횟수와 상한은 `--episodes-per-map 40 --max-steps 700`처럼 지정한다. `--list`는 훈련 없이 맵 목록만 보여준다.

## 현재 범위

원본 x86을 쓰는 **오프라인 단일 플레이어 깃발 이동** 훈련이다. 규칙 봇에 상황별 행동값을 누적한다. 같은 상황 표현을 다른 맵에 옮기지만, 이것만으로 범용 이동 능력이 검증된 것은 아니다. 사용자 직접 조작, 일반 Client 자동 조작, 미니맵 상대 추적, 전투 명중·회피 훈련은 이 실행기에 아직 연결되지 않았다. 용암 접촉 자체는 벌점이 아니며, 용암 근처에서 처음 지역으로 되돌아간 원본 결과만 벌점이다.

현재 `goal:true`는 원본 x86 실행 뒤 플레이어가 깃발의 설정된 판정 영역에 들어왔음을 뜻한다. 별도 원본 깃발 이벤트 신호를 읽은 것은 아니다. 성공 행동열의 재생도 이 동일한 판정으로 확인한다.

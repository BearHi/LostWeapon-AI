# 로컬 물리 탐색·경험 학습

**2026-09-18 공유 모델로 전환:** 현재 `로컬물리_훈련시작.bat`과 `공유두뇌_학습시작.bat`은 모두
`run_shared_learning.py`를 실행한다. [새 구조/사용법](SHARED_LEARNING_DESIGN_2026-09-18.md)을 먼저 본다.
최대 4시간 동안 경험 수집과 공유 모델 학습을 반복하며, 아래의 2순회 최단 기록 정체 종료는
이전 `local_physics_train.py --adaptive`를 직접 실행할 때만 적용된다.
이 문서의 나머지는 물리 경험 수집기 자체에 대한 설명이다.

`로컬물리_훈련시작.bat`을 더블클릭한다. 같은 파일로 중단한 기록을 이어간다.
훈1~20과 훈6.5·7.5·8.5, 총 23개 맵을 순서대로 반복한다. Client를 켤 필요가 없다.
인터넷/API/LLM을 호출하지 않으며, 기존 원본 x86 실행기를 CPU에서 사용한다.

## 실행과 중지

- 시작/재개: `로컬물리_훈련시작.bat`
- 안전 중지: `로컬물리_훈련중지.bat` 실행 후 훈련 창의 종료를 기다린다.
- 결과 요약: `로컬물리_결과보기.bat`
- 9월 18일 개선판 시작 배치: **최대 4시간**, 전체 순회에서 **2회 연속 최선 경로 개선이 없으면 조기 종료**한다. 최대 추가 100순회는 상한이다.
- 개선이 최근 160후보 이내인 맵/미해결 맵은 80후보, 160~399후보 동안 정체한 맵은 40후보, 400후보 이상 정체한 맵은 16후보를 배정한다. 맵당 약 20분 상한도 유지한다.
- 기존 성공 경로 중간에서 입력을 생략하거나 짧게 교체한 뒤 나머지 경로를 이어 시험하는 비중을 늘렸다. 변경한 경로는 시작점 재생을 통과해야 최선 기록에 반영한다.
- `session_time_limit`은 4시간 예산 종료, `diminishing_returns`는 2순회 연속 기록 개선 없음이다. 오류가 아니며 기록은 보존된다. 짧게 끝나면 무작정 재실행하기보다 SUMMARY와 종료 상태를 함께 확인한다.
- 한 후보 = 원본 물리에서 시험한 연속 행동 하나. 전체 맵 1회 플레이와 다르다.
- 각 순회가 끝나면 다음 순회로 넘어간다. 잘된 맵도 더 짧은 경로를 계속 탐색한다.
- 20분 시간 제한은 후보 도중에도 확인한다. 맵 로딩 시간은 별도이며, x86 호출 1회가 끝나야 중지 가능하다.
- Ctrl+C도 지원하지만 중지 배치를 권장한다. 강제 종료하더라도 커밋된 SQLite 기록은 남는다.
- 동일 출력 폴더로 중복 실행하면 두 번째 실행을 거부한다.

CMD에서 실행량 변경:

```bat
python -u local_physics_train.py --resume --adaptive --hours 8 --rounds 300 --trials-per-map 160 --minutes-per-map 30
```

일부 맵만 선택:

```bat
python -u local_physics_train.py --resume --maps 훈5 훈6.5 훈12 --rounds 20
```

탐색 길이 확장:

```bat
python -u local_physics_train.py --resume --horizon 96 --max-steps 1800 --max-nodes 8000
```

`--rounds`는 이번 실행의 추가 순회 수다. 중간 순회는 완료된 맵을 건너뛰고 남은 맵부터 진행한다.
순회 도중 맵 목록을 바꾸면 이미 완료로 기록된 맵은 다음 순회부터 다시 처리한다.
`--out`을 바꾸면 별도 실험이 된다. 중지/결과보기에도 같은 `--out`을 지정해야 한다.

## 무엇을 저장하고 배우는가

기존 5개 항목 행동값 표/DQN을 덮어쓰지 않는 별도 실행기다.
1. 과거 복귀 없는 성공 경로를 읽어 현재 원본 물리로 재생하고, 유효한 도달 지점을 탐색 출발점으로 보존한다.
2. 동일한 원본 상태를 복원해서 서로 다른 연속 행동 후보를 비교한다.
3. 걷기·점프·방향 전환·앞/뒷굴·낙하산·Z·1~4 무기·X와 조합/타이밍 변형을 시험한다. 기존 입력 마스크를 따른다.
4. 9×9 native 충돌 정보, 개별 지형 ID, 동작/방향 상태, 칸 내부 위치, 마지막 입력을 맥락으로 저장한다. 진행 중에도 8결정마다 다시 읽는다.
5. 같은 맥락에서 보상 결과가 좋았던 기술을 우선 시험하며, 무작위 후보도 남겨 새 해법을 탐색한다.
6. 도달 상태 모음에서 덜 시험한 지점을 다시 선택하므로 깃발 반대 방향 우회도 탐색한다.
7. 기존 성공 경로 중간부터 다른 기술이나 입력 생략을 시험하고, 더 짧은 성공열은 시작점부터 재검증한다.

용암 접촉/피격/눕기 자체는 실패로 처리하지 않는다. 실제 native 결과가 계속 전진하면 후보로 남긴다.
시작 근처로 큰 폭으로 순간 복귀하면 `reset_suspected`로 제외한다. 이 판정은 좌표 변화 추정으로, 원본 리스폰 이벤트 판독이 아니다.
의도적인 순간이동 등이 있는 맵에서 잘못 제외될 수 있으므로 해당 실패 기록을 함께 본다.
캐릭터 상태만 비슷하다는 이유로 성공을 보장하지 않는다. 도달 상태의 위치 구간은 탐색 분산용이다.
현재 맵의 원본 상태 전체를 복원/재생해 후보를 실행한다.

## 효율과 범위

- 원본 snapshot을 매 후보마다 다시 로딩하지 않는다. 같은 출발 상태에서 메모리 분기를 사용한다.
- 자주 사용하는 도달 상태는 기본 96MB 내에서 임시 보관한다. 맵 간에는 별도 프로세스로 메모리를 회수한다.
- 후보마다 기록을 커밋한다. 중단한 후보 하나는 다시 시험할 수 있다.
- 맵당 도달 상태 기본 한도는 4,000개다. 한도에 도달하면 `--max-nodes`를 늘릴 수 있다.
- 오래 돌린다고 성공/최적 경로가 보장되지는 않는다. 탐색 예산이 끝나면 다음 맵으로 넘어간다.
- native 오류/물리 버전 불일치는 자동 재시도 루프를 돌지 않고 전체 실행을 멈춰 오류를 남긴다.
- 이 버전은 **오프라인 탐색과 경험 축적기**다. 일반 Client의 실시간 조종기나 새 맵 일반화 신경망은 아니다.
- 전체 맵이 들어 있는 물리 실행기에서 경로를 시험하므로, 엄격한 ‘미지의 맵을 9×9 시야만으로 탐험’ 평가도 아니다.
- 9×9 관측과 별도로 원본 물리 세계의 연속 결과를 확인한다. 피해 유도는 기존 맵 기믹에서 시험 가능하지만, 살아 있는 상대의 공격 유도/전투 학습은 이 단일 플레이어 훈련 범위에 없다.

## 결과 위치와 의미

`checkpoints/local_physics_v1/`

- `SUMMARY.md`: 대화에 붙여줄 짧은 맵별 요약.
- `훈N.sqlite3`: 후보 성공/실패, 입력열, 맥락, 도달 상태, 학습한 기술 우선순위. 실행 중에는 `-wal`, `-shm`도 함께 사용한다.
- `훈N.best.json`: 깨끗한 시작점에서 재생 확인한 최단 **시험 경로**. 전역 최단 보장은 아니다.
- `훈N.summary.json`: 후보 수·도달 상태 수·최선 결정 수·종료 원인.
- `curriculum.json`: 순회와 재개 위치.

`goal_region`은 오프라인 원본 x86 실행 뒤 기존 깃발 좌표 영역 도달 판정이다.
일반 Client의 깃발 이벤트/게임 클리어와 동등하다고 검증한 기록이 아니다.
`horizon`은 제한한 기술 길이가 끝났다는 뜻이며 실패 판정이 아니다.
기존 경로를 가져온 성공과 새로 탐색한 후보/개선 결과는 DB에서 `mode`로 구분한다.

기존 `route_rule_helper`, `route_curriculum`, DQN 파일과 원본 LMF/snapshot은 읽기만 한다.
백업은 안전 중지 후 새 폴더 전체를 복사한다. 실행 중 SQLite 본체 파일만 복사하지 않는다.

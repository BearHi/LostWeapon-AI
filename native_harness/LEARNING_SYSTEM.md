# 로스트웨폰 지속 학습 기준

## 목표

한 맵의 입력열을 외우는 것이 아니라, 새 맵을 스캔하고 현재 물리 상태를 읽어
이동·사다리·수영·낙하산·기믹·전투 조각을 선택하고 재조합하는 에이전트다.
채팅은 작업 인터페이스일 뿐 두뇌의 저장소가 아니다. 모든 학습 근거는 이
디렉터리의 코드·체크포인트·경험 기록으로 재현할 수 있어야 한다.

## 현재 사실 (2026-09-16)

- 원본 훈련맵은 모두 적어도 한 번 네이티브 클리어했다. 이는 독립 정책의
  100% 성공률을 뜻하지 않는다.
- 변형 `혼` 23개 × 3회에서는 최초 25/69회 클리어, 10개 맵에서 성공했다.
  이후 혼2를 맵 구조 기반 조각 재조합으로 클리어·재검증했다.
- 저장 경로 안내와 탐색기를 끈 공용 DQN 단독 평가는 훈5·훈7·혼2·혼5
  네 맵 모두 500결정 안에 실패했다 (`evaluate_policy_only.py`).
- 임시 균형 복습 실험은 훈5·혼2 동시 단독 클리어를 한 번 만들었지만 재실행
  결과가 흔들렸다. 복귀 상태를 가장 가까운 성공 경로 행동으로 라벨링하는
  실험도 혼2를 안정화하지 못했다. 임시 모델은 공용 체크포인트로 승격하지 않았다.
- `solve_map_physics.py`는 인간 녹화·DQN 없이 지도 구조에서 물리 행동 가설을
  선택해 원본 x86 전이로 검사한다. 성공하면 처음 상태에서 재실행한 경로만
  `checkpoints/physics_route_library.json`에 보관하며, 사용할 때도 다시 재검증한다.
  2026-09-16 검증: 훈1~7, 훈8.5, 훈9~12와 혼2·혼10이
  성공했다. 훈6.5·훈7.5·훈8·혼8.5·혼9는 이 탐색기의 현재 범위에서 미해결이다.
  이는 오프라인 원본-x86 목표 접촉이지 온라인 게임 클리어 증거가 아니다.
- 물리 규칙의 유효 범위: 훈6은 위 입력 실패 뒤 구르기 출발로 해결됐으나
  훈6.5에는 일반화되지 않았다. 훈8.5는 지면 정착→raw4 발동 감지→목표 x로
  조향해 해결됐다. 훈9·훈10은 1틱 입력으로 뒤로 물러나 방향을 맞춘 뒤
  raw5/6 대각 스프링을 구르기로 접촉했다. 혼10에서는 물러나는 길이를
  8틱에서 6틱으로 바꿔 해결했지만 혼9는 발동하지 않았다.
- 입력 제한은 사다리·물·펼친 낙하산의 확인된 무효 키와 `위+C`만 강하게
  적용한다. 발판 접촉 판정만으로 `왼쪽+C`/`오른쪽+C`를 지우지 않는다.
  다음 원본 틱에 구르기·스프링·낙하로 상태가 변할 수 있기 때문이다.
  피격 중 연타·숫자키·X도 함부로 막지 않는다. `좌/우+아래+Z` 동시
  입력은 기존 행동 뒤에 추가했고 기존 번호는 바꾸지 않았다. 더 중요한
  `좌/우+아래 → Z` 순차 캔슬도 가능하다. 원본 x86에서 구르기 1~4틱째
  상승 중 Z를 누르면 즉시 공격 상태 15로 전환되는 것을 확인했다.
- `무기금지·점프금지·구르기금지·낙하산금지`는 **맵 안의 블록**이며
  방 모드와 별개다. 사용자 제공 `금지블록.LMF` 배치로 raw136=점프,
  raw137=구르기, raw138=낙하산, raw139=무기임을 확인했다. 사용자 규칙대로
  블록 기준 좌우 5칸·상하 4칸(경계 포함) 안에서 각각 위 점프, 방향+아래,
  C, Z 요청을 후보에서 제외한다. 물속의 위 수영과 사다리 오르기는 점프가
  아니므로 유지한다. 숫자 무기 선택과 X 스위치는 별도 효과 확인 전까지
  유지한다. 이 범위는 사용자 제공 규칙의 구현이며 원본 x86 경계 검증은 별개다.
  맵/전투 관찰에 네 금지 상태를 별도 특성으로 넣고, 행동 선택뿐 아니라
  DQN의 다음 상태 가치 계산에서도 무효 행동을 제외한다.
  raw136/138을 특수 이동 장치로 오분류하던 부분을 제거했다. 금지 블록만
  있는 맵에 목적지 방향 보상을 붙이지 않으며 훈6의 제한 적용 경로는
  원본 x86 시작점 재실행으로 다시 통과했다.
- 기존 공용 맵 체크포인트는 19개 행동만 학습했다. 21행으로 메모리상
  확장하더라도 단독 평가는 미학습 2행을 제외해 기준선을 보존한다.
  2026-09-16 훈1·훈2 단독 평가에서는 각각 88결정으로 목표에 닿았다.
  이는 구르기 캔슬 학습이나 새 맵 일반화의 증거는 아니다.

## 두뇌의 층

1. **고정된 세계 인터페이스:** 원본 Client x86 물리를 유일한 전이 기준으로
   쓴다. 지도 전체, 주변 충돌·오브젝트, 플레이어 상태, 입력 상태를 관찰한다.
   물리 추정치와 실제 확인 결과를 구분한다.
2. **검증 가능한 경험:** 체크포인트의 에피소드·경로·발판 간 전이 조각을
   지도 해시, 물리 버전, 시작 상태, 행동과 결과와 함께 보존한다. 옛 경험은
   새 맵에서 반드시 네이티브로 재실행해 확인한다.
3. **상황별 기술:** 걷기/도약/착지, 사다리, 수영, 낙하산, 특수 이동과 전투를
   별도 기술로 익히되 상위 의사결정은 공유한다. 기술은 특정 맵 좌표가 아닌
   발판·목표·물리 상태를 입력으로 받는다.
4. **학습 정책:** 여러 맵의 성공과 실패를 섞어 복습한다. 한 맵 직후의 모델
   가중치뿐 아니라 맵별 성공 관찰·행동 표본도 후보 체크포인트에 보존한다.
   이 균형 복습은 구현했지만 신경망 단독 일반화는 아직 입증되지 않았다.
5. **승격 게이트:** 새 정책을 기본 두뇌로 바꾸기 전, 저장 경로·탐색기 없이
   원본과 보지 않은 변형맵을 반복 평가한다. 기존 성능 저하, 불안정한 재실행,
   우회로만 이용한 가짜 기믹 성공은 실패로 기록한다. 실패 모델은 별도 보관하고
   기존 모델을 유지한다.

## 다음 구현 순서

2026-09-17 물리 우선 이동 점검: DQN 기본 관찰은 9×9로 유지한다. 별도의
`adaptive_navigation_view`는 현재 원본 x86 충돌 격자와 LMF 오브젝트를
매 결정 다시 읽고, 다음 발판 틈이 9×9 밖이면 10부터 최대 15칸까지
필요한 만큼 넓힌다. 훈1은 9×9, 훈2는 시작점에서 13×13이었다.
목표 좌표·다음 발판 경계·틈 너비는 전체 지도에서 별도로 계산한다.
`run_physics_first.py`는 저장 경로나 모델을 사용하지 않고 일반적인
수평 이동 후보를 원본 물리로 시험해 최단 **후보**를 선택한다.
훈1 앞굴 53결정, 훈2 점프 후 앞굴 54결정, 혼2 변형 56결정을
깨끗한 시작점에서 재검증했다. 이는 제한된 후보 집합 내 최단이며 모든
가능한 키열의 전역 최단 증명이 아니다. 수직/복합 기믹 맵은 이 계산기가
아직 풀지 못하면 추측하지 않고 실패를 보고한다. 오브젝트 ID는 LMF
배치 기준이므로 움직이는 런타임 오브젝트의 실시간 위치와 동일하다고
가정하면 안 된다. 학습 보상은 결정당 시간 비용 -0.05, 실제 깃발 접촉
100점과 남은 시간에 비례한 최대 100점을 준다. 맵별 성공 관찰·행동을
후보 체크포인트에 저장해 균형 복습하지만, 훈1·훈2 두 맵으로 학습한
모델의 단독 평가는 훈1만 성공했다. 그러므로 물리 계산기를 우선 제어기로
두고 DQN은 아직 승격하지 않는다.
훈3에서는 앞굴만 누르면 벽에 막힌 뒤 낙하·리스폰한다. 물리 후보 실행을
리스폰 직후 중단하도록 바꿨고, 현재 찾은 성공 후보는 점프 6결정 뒤 앞굴
63결정이다. 걷기 12결정 뒤 앞굴도 65결정에 성공했다. 사용자가 말한
더 빠른 구르기 중심 경로는 아직 확인하지 못했으므로 훈3 최적이라고
주장하지 않는다.
구르기 후보는 원본 물리에서 관찰된 막힘 좌표·최대 전진 좌표·마지막 발판
접촉점을 기록한다. 훈3 순수 앞굴은 x=238 부근에서 막혀 20결정째
리스폰했다. 이미 N결정짜리 성공 경로가 있으면 다른 후보는 N-1결정 안에
성공하지 못할 경우 더 빠를 수 없으므로 중단한다. 이것은 후보 제거에
관한 정확한 시간 경계지만, 현재 수평 후보 19종 밖의 모든 키열에 대한
전역 최적화는 아니다. 학습 모델의 9×9 입력과 별개로 물리 계산기는
전체 지도에서 목표·발판을 확인하고 필요한 경우 주변 창을 점차 넓힌다.
훈4는 목표가 왼쪽인 새로운 수평 지형에서 왼쪽 점프 2결정 후 구르기
58결정으로 깨끗한 native 시작점 재실행에 성공했다. 9×9에서 최대 15×15로
시야를 넓혀도 멀리 있는 발판 경계가 다 보이지 않을 수 있으므로, 전체 지도
발판 정보와 국소 창을 함께 사용한다.
로컬 전체맵 실행은 통합 UI `LostWeapon_Native_AI.bat`의 `폴더 자동 학습`
버튼으로 시작한다. 같은 UI에 현재 맵/틱/보상/오프라인 깃발 영역 도달 수가
표시되고 `폴더 학습 중지` 버튼으로 현재 자식 학습까지 멈춘다. UI를 닫았다가
다시 열 필요 없이 버튼으로 재개할 수 있다. `학습_전체맵_CMD.bat`도 오류가
나지 않도록 통합 UI를 여는 호환용 진입점으로 바꿨다. 선택한 폴더 아래
플레이 가능한 맵을 재귀적으로 찾고, 각 맵은 최대 3회 시도하되 목표 영역
도달 시 다음 맵으로 넘긴다. 기록과 후보 모델은
`checkpoints/physics_first_local`에 격리되며 공용 모델을 자동 교체하지
않는다. 이것은 오프라인 native 학습이지 온라인 계정 플레이가 아니다.

맵 학습 행동에 `좌/우+아래+Z`를 기존 번호 뒤에 추가했다. 원본 x86에서
동시 입력 시 공격 상태와 구르기형 이동이 함께 관찰됐지만, 상대 피해까지
검증한 것은 아니다. 물·사다리·펼친 낙하산 상태에서는 이 조합을 제외하고,
피격 회복이나 발판 이탈처럼 경계가 애매한 상태에서는 원본 물리가 판단하게
둔다. 기존 19개 행동 번호와 저장 경로는 유지하고, 구형 DQN의 출력 19행은
신형 21행의 앞부분으로 이식하되 최적화 상태는 초기화한다. 전투 전용
학습기의 행동 목록도 같은 조합을 뒤에 추가했다. 전투 체크포인트의 이전
관찰 열과 행동 출력 행을 이름/번호로 이식하며 최적화 상태는 초기화한다.
이 조합의 실제 상대 피해나 전투 훈련 성능 개선은 아직 검증하지 않았다.
전투 학습/보기에서도 관찰된 사다리·물·낙하산 상태에서 무효인 행동은
선택 및 다음 상태 가치 계산에서 제외한다. 피격 회복 상태는 제한하지 않는다.

1. 현재 네이티브 경로 조립기와 성공 기록은 유지한다. 이것은 실제로 작동하는
   기술 기억이며 신경망 단독 성공과 혼동하지 않는다.
2. 성공 경로와 실제 이탈 상태에서 **네이티브로 재연결에 성공한** 짧은 복귀
   전이만 학습 자료로 만든다. 단순히 위치가 가까운 행동을 정답으로 붙이지 않는다.
3. 오래된 맵과 새 맵을 균등 복습하는 별도 후보 모델을 학습한다. 공용 기준
   체크포인트는 덮어쓰지 않는다.
4. `evaluate_policy_only.py`로 안내 없는 단독 플레이를 반복 평가하고, 처음
   보는 변형맵도 검사한다. 통과한 후보만 공용 두뇌로 승격한다.
5. 이후 칼전·기믹 학습을 같은 관찰/경험 저장 규약으로 추가한다. 게임방과
   제작방의 자료는 구분하되 공통 세계 이해와 기술 선택은 재사용한다.

## 용어

`native_verified`는 원본 Client 명령으로 해당 행동열이 그 맵에서 목표에
닿았다는 뜻이다. `policy_only`는 저장된 행동열이나 계획기의 도움 없이
모델이 매 순간 고른 행동만으로 진행했다는 뜻이다. 어느 쪽도 아직 실제
온라인 계정 플레이를 증명하지 않는다.

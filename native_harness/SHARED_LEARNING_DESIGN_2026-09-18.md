# 공유 물리 결과 학습기

## 이번 점검에서 확인한 원인

기존 실행은 20순회 후 `diminishing_returns`, 2순회 연속 최단 경로 개선 없음으로 종료했다.
중지 기준은 학습 성능과 별개였다. 30,184개 후보 시험에 대해 상황/기술 표 28,150개 중 93.7%가 1회 관측뿐이었다.
정확한 상태/지형/목표의 해시가 달라지면 경험을 공유하지 못했고, 맵별 DB끼리도 학습을 공유하지 않았다.
또한 `compose_1`, `RIGHT_jump_roll` 등 같은 이름이라도 입력열과 타이밍이 달랐지만 기존 표는 이름 단위로 평균냈다.

## 목표와 구현 범위

최종 목표는 깃발 이동. 현재 원본 상태와 주변 지형에 따라 가능한 기술을 비교한다.
용암/피격/눕기 자체를 금지하지 않는다. 원본 물리에서 통과하는지와 복귀 여부를 판단한다.
이번 변경은 이 구조의 **공유 결과 예측 모델 + 원본 물리 경험 수집 루프**를 구현한다.
완전한 전역 길찾기·실시간 Client 실행·미니맵 전투·수동 개입 처리는 이 모델의 완성 판정에 포함하지 않는다.
후속 구현에서도 이 요구는 버리지 않는다. 특히 공격 OFF와 이동 기술로 사용하는 Z/무기는 분리해야 한다.

## 구조

1. **확정 물리/입력 마스크**: 기존 native 환경을 그대로 사용한다. 모델이 물리를 대신하거나 새 금지 규칙을 만들지 않는다.
2. **관측**: 9×9의 4개 충돌층, 칸별 오브젝트 ID(중첩 최대 4개), 캐릭터 동작·방향·낙하산 등 노출된 원본 필드, 칸 내부 위치, 유지 중인 키.
3. **행동**: 기술 이름 대신 최대 64결정의 시간 순서/지속 길이를 입력한다. 기존 21개 행동과 조건부 좌/우 낙하산 행동을 구분한다.
4. **공유 모델**: 모든 학습 맵에 같은 작은 PyTorch CNN/MLP 가중치를 사용한다. 도착 변위, 실행 길이, 복귀/맵 이탈 위험을 예측한다. 맵 이름·절대 좌표·정확한 상황 해시·깃발 좌표는 모델 입력에서 제외한다.
5. **후보 선택**: 예측이 좋은 후보를 우선 native 시험한다. 절반의 후보는 계속 무작위로 남긴다. 예측을 근거로 기술을 금지하거나 안전 판정을 확정하지 않는다. 학습에 없던 행동 토큰은 모델 점수 적용을 보류한다.
6. **결과 저장**: 요청한 기술/타이밍, 실제 입력열, 시작/도착 상태와 결과를 함께 저장한다. 성공·실패가 모두 다음 모델 학습에 들어간다.
7. **재학습**: 수집 → 공유 가중치 업데이트 → 별도 검증 → 통과한 모델만 후보 우선순위에 반영한다.

기존 경로 라이브러리는 native 시작 상태를 재구성하는 데 계속 활용한다. 정확한 상태 복제 후 후보를 시험하므로 물리적 가능성 판단은 모델 추측과 구분된다.
전체 맵의 native 세계를 사용하는 오프라인 수집이다. 모델 입력만 국소 지형인 것이며, 미지의 맵 탐험 정책을 검증했다는 뜻은 아니다.

## 기존 경험의 재사용

기존 로그에는 요청한 원래 기술 계획이 없다. 따라서 과거 기술 이름을 정답으로 삼지 않는다.
기록된 실제 입력열을 고정 입력 기술로 해석해 시작 상태→결과의 감독 학습 자료로 사용한다.
64결정을 넘는 예제, 맥락이 없는 예제, 원본 물리 fingerprint가 다른 자료는 제외/거부한다.
새 경험부터는 `planned_phases`, `plan_budget`을 추가해 조건부 낙하산과 입력 마스크가 적용되는 원래 계획도 학습한다.
긴 전체 경로 재생 기록을 짧은 예측 모델에 잘라 넣고 전체 경로 결과를 라벨로 붙이지 않는다.

## 실제로 무엇이 학습되는지 확인하는 기준

- 훈3·훈7.5·훈13·훈19는 고정 검증 맵으로 가중치 업데이트에서 제외한다. 해당 맵의 native 수집 기록은 별도 평가 자료다.
- 나머지 맵도 같은 상황에서 나온 후보가 학습/검증 양쪽에 흩어지지 않도록 상황 단위로 분리한다. 유사 상황 누수 가능성은 맵 전체를 제외한 평가와 구분해서 해석한다.
- 위치 예측 오차, 복귀 위험 Brier, 실행 길이 오차를 보고한다. 최단 기록만으로 학습의 유무를 판단하지 않는다.
- 맥락 검증과 제외 맵 검증 모두에서 단순 평균 예측보다 위치 오차가 10% 이상 낮고 위험 Brier도 좋아야 후보 안내 자격을 얻는다. 기존 안내 모델보다 맥락 검증 종합 점수도 좋아야 교체한다.
- 9월 18일 후속 보강: 학습에서 제외한 맵의 **동일 replay prefix·동일 상황·동일 예산**에서 나온 계획 후보들을 묶어 고정 비교 집합을 만든다. 현재 500개 상황이다. 후보가 충분하지 않은 초기 자료는 모델 교체를 보류하고 수집을 계속한다.
- 새 모델은 고정 후보 비교에서 무작위 평균보다 전진/위험/시간 종합 점수가 좋아야 한다. 선택한 복귀·이탈 비율이 무작위 또는 기존 모델보다 0.5%p 넘게 나빠지거나, 기존 모델보다 종합 점수가 0.01 넘게 떨어지면 교체하지 않는다.
- 학습에서 제외한 맵의 위치 오차가 기존 모델보다 2% 넘게 커지거나 위험 Brier가 0.002 넘게 커지는 모델도 교체하지 않는다. 가중치를 바꾸기 전에 같은 현재 평가 자료로 기존 모델을 다시 비교한다.
- 후보 순위의 위험 가중치를 3에서 6으로 올렸다. 이것은 안전성 보장이 아니며, 후보의 실제 결과는 계속 원본 물리로 확인한다.
- `candidate_benchmark.json`은 고정 비교 집합, `learning_history.jsonl`은 이후 학습 회차별 성적과 교체 여부를 누적 기록한다. 평가 집합 자체를 훈련에 넣지는 않는다. 이 자료 역시 모델 선택에 쓰는 검증 집합이지 최종 독립 게임 테스트는 아니다.
- 이는 **예측 모델 검증**이다. 실제 주행 성공률, 새 맵 해결률, 수동 개입 후 복구 능력은 별도 native/Client 평가가 필요하다.
- 현재 노출된 상태만으로 숨은 수평 운동/동적 기믹을 완전히 표현한다는 보장은 없다. 오차를 통해 부족한 관측을 찾아야 한다.
- 용암 후 리스폰 라벨은 기존 위치 급변 추정이다. 그 오차를 없앤 것으로 주장하지 않는다.

## 사용자 실행

`공유두뇌_학습시작.bat`을 실행한다. 기존 `로컬물리_훈련시작.bat`도 같은 공유 학습 실행기로 연결했다.
두 배치를 동시에 실행하면 두 번째 실행은 잠금으로 거부한다.
기본 4시간 동안 **학습(최대 15epoch) → 23개 맵 새 경험 수집 → 재학습**을 반복한다.
모델 학습 한 번은 검증 성능이 4epoch 연속 좋아지지 않으면 끝내고 다음 수집으로 넘어간다.
전체 실행은 최단 기록 2순회 정체로 끝나지 않는다. 4시간/지정한 cycle 상한/사용자 중지/명시적 오류가 종료 조건이다.

- 중지: 기존 `로컬물리_훈련중지.bat`.
- 8시간: `python -u run_shared_learning.py --hours 8`
- 기존 자료만 학습: `python -u run_shared_learning.py --fit-only --epochs 15`
- 결과: `checkpoints/shared_physics_v1/MODEL_SUMMARY.md`, `model_report.json`, `learning_status.json`.
- `latest.pt`: 최근 학습 모델. `active.pt`: 검증을 통과해 수집에 사용하는 모델.
- 첫 실행 때 기존 23개 DB를 SQLite backup API로 별도 보관한다. 이후 새 native 경험은 기존 DB에 추가하며 과거 기록은 지우지 않는다.
- CPU에서 동작하고 인터넷/API 호출은 없다. GPU가 없어도 실행된다.

## 다음 단계의 통과 조건

공유 모델의 예측 성능 확인 다음에는 고정된 시작 상태 집합에서 동일한 후보·동일한 native 계산 예산으로
모델 안내/무작위 안내/기존 규칙을 비교해야 한다. 원본 시작 위치를 임의로 메모리에서 바꾸지 않고,
실제 입력으로 도달한 상태에서 시작 방향·속도·타이밍을 바꿔 평가한다.
이 비교에서 성공률·안전 통과·계산량이 좋아져야 실시간 기술 선택기로 승격한다.
이후 전역 경로/발견 지도는 중간 목표를 주고, 이 모델은 그 구간의 기술 후보를 제안하는 계층으로 연결한다.

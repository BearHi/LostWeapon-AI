# 깃발 우선 헬퍼 설계 — 2026-09-17

이 문서는 설계안이다. 사용자가 훈련을 실행한다. 이 문서를 작성하면서 학습·평가를 실행하거나 체크포인트를 교체하지 않는다.

## 제어 원칙

헬퍼의 기본은 일반 게임 봇처럼 **규칙으로 즉시 행동하는 결정형 제어기**다. 원본 물리 상태와 지형으로 가능한 행동을 추리고, 깃발을 향한 경로·위험·소요 시간을 비교해 행동한다. 보상과 훈련도 유지한다. 훈련은 이 기본 제어기가 여러 가능한 행동 중 무엇을 우선할지, 어느 물리 기술이 해당 상황에서 잘 되는지를 개선한다. 훈련 결과가 없거나 확신이 낮아도 기본 제어기로 움직일 수 있어야 한다.

보상은 깃발 접촉을 최우선으로 두고, 진행·실제 명중·실제 회피를 보조한다. 보상 숫자 자체가 주행 중 길찾기를 대신하지 않는다. 사용자가 훈련을 실행하고, 헬퍼는 원본 x86 결과를 경험으로 저장한다.

### 위험 지형과 시작 지역 복귀

- 용암·지옥문 등은 **접촉 금지 칸으로 고정하지 않는다**. 용암 맵에서는 구르기로 접촉 구간을 통과하며 앞으로 전진하는 경로가 필요하다. 지형 ID만 보고 피해나 실패를 확정하지 않고 원본 물리 결과로 판단한다.
- 접촉 그 자체의 보상은 0이다. 접촉 후 살아서 전진하고 깃발 경로가 개선되면 일반 진행 보상을 받는다.
- 접촉 결과로 **처음 지역으로 되돌아갔을 때** 벌점을 준다. 판정은 시작 지역 좌표만으로 하지 않고, 접촉 뒤 원본 상태의 리스폰/위치 급변과 진행 구간 상실을 함께 확인한다. 계획된 우회로 잠깐 시작 지역을 지난 것에는 벌점을 주지 않는다.
- 리스폰을 일부러 이용해 길을 단축하는 경로는 기본 봇의 후보에서 제외한다. 특수 맵 예외는 별도 원본 증거와 사용자 지시가 있을 때만 추가한다.

### 기본 봇의 행동 우선순위

1. 기존 입력 마스크로 현재 물리 상태에서 무효인 키를 제외한다.
2. 현재 위치에서 깃발까지 알려진 경로가 있으면 그 경로의 다음 구간을 목표로 잡는다. 없으면 깃발 쪽으로 연결될 가능성이 높은 미지의 경계를 목표로 잡는다.
3. 물리 기술로 몇 개의 짧은 행동을 예측한다. 후보별로 `깃발 경로 진전`, `실제 통과 이력`, `시작 지역 복귀 위험`, `소요 시간`, `상대 위협`을 비교한다. 위험 지형 접촉 여부만으로 후보를 버리지 않는다.
4. 전투 우선 모드에서 상대가 공격 가능하면 짧은 공격·회피 행동을 끼워 넣는다. OFF에서는 공격하지 않는다. 두 모드 모두 최종 목표는 깃발이다.
5. 한 행동을 원본 물리로 실행하고 실제 결과를 기록한 뒤 다시 1번부터 판단한다. 막히거나 밀리거나 예상과 다르면 이전 입력열을 계속 밀어붙이지 않는다.

이 순서는 훈련 전에도 동작한다. 훈련은 3번의 성공률·시간·위험 예측과 후보 우선순위를 보정한다. 사용자가 직접 조작하면 헬퍼 입력을 중단하고 조작 종료 후 1번부터 다시 판단한다.

## 목표와 스위치

- 모든 모드의 최종 목표는 원본 Client 판정의 **깃발 접촉**이다. 직선 최단거리보다 실제 통과 가능한 빠른 경로를 우선한다.
- `combat_mode=off`: 상대에게 공격을 시도하지 않는다. `1~4` 무기 선택도 이동에 필요한 효과가 원본 물리에서 확인된 경우만 후보로 둔다.
- `combat_mode=priority`: 공격 가능한 상대에게 명중하거나 위협을 피하는 단기 행동을 허용한다. 전투로 깃발 진행이 무한히 지연되면 이동 목표로 복귀한다.
- 기존 행동 번호와 사다리·물·낙하산·금지블록의 입력 마스크를 재사용한다. 물리 상태를 무시한 새 금지 키 규칙을 만들지 않는다.
- 사용자가 언제든 직접 조작할 수 있다. 사용자 입력이 감지되면 헬퍼 입력을 즉시 내려놓고, 손을 뗀 뒤 현재 원본 상태를 다시 읽어 경로를 새로 고른다.

## 관측은 두 범위로 나눈다

- **국소 지형:** 플레이어 주변 가변 5×5~21×21. 벽·발판·기믹·현재 물리 상태로 다음 행동의 가능성을 판단한다.
- **전역 목표/상대:** 깃발 좌표와 미니맵에서 확인 가능한 상대 위치를 별도 입력으로 둔다. 상대가 국소 지형 밖에 있어도 위치와 마지막 관측 시각을 유지한다. 미니맵 표시가 가려지거나 갱신되지 않으면 `미확인`으로 두며 현재 위치로 단정하지 않는다.
- 상대 추적에는 `마지막 위치·관측 시각·추정 이동 방향·위치 불확실성`을 둔다. 새 관측이 없을수록 불확실성을 키운다. 위쪽 발판의 상대가 아래로 떨어질 수 있으므로 수평 거리뿐 아니라 **높이 차이와 낙하 가능한 통로**를 위협 계산에 포함한다.
- 미니맵 위치와 실제 원본 player 좌표의 대응, 갱신 주기, 가림 조건은 별도 검증 대상이다. 오프라인 캡처에서 보이는 상대 슬롯과 실제 화면 미니맵이 동일하게 제공된다고 가정하지 않는다.

## 한 결정의 흐름

1. 원본 x86 상태에서 현재 위치·속도/동작 상태·입력 유지 상태·깃발 좌표·주변 지형과 물체를 읽고, 확인 가능한 미니맵/상대 관측을 합친다.
2. 현재 맵의 발견 지도를 갱신한다. 각 칸은 `unknown / open / blocked / boundary`로 기록한다. 동적 물체와 시간에 따라 바뀌는 칸은 관측 시각도 보존하고 다시 확인한다.
3. 플레이어 중심 **5×5**에서 시작한다. 깃발 쪽 출구, 착지점, 위아래 우회로를 판단할 수 없으면 반경을 한 칸 늘려 7×7, 9×9, 11×11 … 최대 21×21까지 읽는다. 판단이 가능하면 즉시 멈춘다. 4×4는 중심이 모호해 기본값으로 쓰지 않는다.
4. 발견한 지도에 두 종류의 연결을 둔다. `가설 연결`은 지형과 배운 물리로 도달 가능해 보이는 후보이고, `검증 연결`은 현재 원본 x86 실행에서 성공한 전이다. 빈칸만 보고 검증 연결로 승격하지 않는다.
5. 깃발까지의 알려진 통로와 미지의 경계(frontier)를 훑어 짧은 후보 경로 몇 개를 만든다. 맨해튼 직선거리는 동률 정리용으로만 쓴다. 경로가 끊기면 깃발에 가까운 미지 경계를 탐색 목표로 삼는다.
6. 후보의 첫 구간에 대해 현재 물리 상태에서 가능한 걷기·점프·구르기·낙하산·사다리·기믹·무기 행동을 고른다. 물리 기술은 후보 생성에 쓰고, 실제 성공·막힘·리스폰 결과를 다시 지도에 반영한다.
7. 국소 시야 밖 상대도 전역 추적으로 확인한다. 위에서 낙하 가능한 상대가 가까우면 한두 행동 앞의 충돌 위험을 먼저 평가한다. `combat_mode=priority`일 때만 공격 후보를 이동 후보와 비교한다. OFF에서도 생존을 위한 회피는 가능하지만 공격 입력은 쓰지 않는다. 전투가 불가능하거나 제한 시간을 넘으면 깃발 경로로 돌아간다.

## 사용자 직접 조작의 처리

- 입력 우선순위는 `사용자 > 헬퍼`이다. 두 입력을 섞지 않는다. 사용자 키를 누른 시점부터 헬퍼가 낸 유지 키를 해제하고 `manual` 구간을 기록한다.
- 사용자가 손을 떼면 짧은 안정 구간 뒤 현재 위치·물리 상태·지도·상대를 다시 읽는다. 예전 행동열의 중간부터 재생하지 않고 새 상태에서 재계획한다.
- `manual` 구간의 `(상황, 사용자 입력, 원본 결과)`는 별도 기록으로 보관한다. 먼저 같은 상황에서 헬퍼가 왜 정체했는지 찾는 **참고 자료**로 사용한다. 사용자의 긴급 개입을 자동 정답 라벨이나 직접 보상으로 삼지 않는다.
- 사용자가 개입한 에피소드와 헬퍼 단독 에피소드는 성공률을 별도로 보고한다. 단독 성능 평가에는 사용자 개입 구간을 넣지 않는다.

## 물리 선행 학습 구조

- 기본 제어는 `원본 물리 상태 → 유효 행동 판정 → 짧은 행동 결과 예측 → 깃발 경로/위험 비교 → 한 행동 실행` 순서로 항상 동작한다. 훈련은 예측의 성공률과 후보 우선순위를 보정하며, 제어 규칙을 통째로 대체하지 않는다.
- 작은 상황별 훈련: 평지 걷기/정지, 턱/벽, 틈/착지, 점프와 앞·뒤 구르기, 사다리, 물, 낙하산, 얼음, 스프링, 자석, 이동·파괴 물체, 금지블록, 무기별 이동·공격. 확인되지 않은 기믹은 별도 `unknown mechanic`으로 남긴다.
- 한 기록의 키: **상대 지형 모양 + 플레이어 물리 상태 + 유지 중인 키 + 물체 상태 + 행동 길이**. 절대 맵 좌표와 맵 이름만으로 기술을 찾지 않는다.
- 기록값: 원본 x86에서 측정한 이동량, 착지/충돌/피격/리스폰, 소요 결정 수, 성공률, 적용 가능한 상태 범위, snapshot·LMF·물리 버전. 실패도 저장한다.
- 새 지형에서 저장 기술을 쓰기 전 현재 상태와 적용 범위를 대조한다. 성공 경로는 시작 상태부터 원본 x86으로 재실행해 검증한다. 기존 경로 조각은 정답이 아닌 후보이다.
- 기술 성능이 부족한 상황만 다시 학습하고, 이미 확보한 기술과 경험을 보존한다.

## 보상 초안

최종 수치는 훈련 결과로 조정하되 **깃발 보상 > 한 에피소드의 모든 보조 보상**을 유지한다.

| 사건 | 초기 설계값 | 중복 방지 |
|---|---:|---|
| 원본 깃발 접촉 | +100 | 에피소드 한 번 |
| 발견 경로의 깃발까지 남은 비용 감소 | 최대 +0.5/결정 | 동일 상태 재방문으로 재지급하지 않음 |
| 유효한 새 통로/물리 전이 확인 | +0.2 | 같은 맵·상태·전이는 한 번 |
| 상대 HP 실제 감소 (`priority`만) | 감소량에 비례, 결정당 최대 +0.5 | 자기 피해·환경 피해 제외 |
| 확인된 공격 위협 회피 (두 모드) | +0.2 | 위협 하나당 한 번, 실제 회피 판정 필요 |
| 결정 시간 비용 | -0.05 | 매 결정 |
| 위험 접촉 뒤 시작 지역 복귀 | -5 | 원본 리스폰/위치 급변과 진행 상실로 확인; 접촉만으로는 0 |
| 같은 상태에서 행동 반복·장기 정체 | 추가 음수 | 진전 없는 연속 구간만 |

경로 비용은 **발견·검증된 연결의 예상 결정 수**를 사용한다. 아직 연결이 없는 동안에는 새로운 frontier 발견을 보조 신호로 사용한다. 이전 최선보다 나아진 경우만 진행 보상을 지급하고, 되돌아가야 하는 우회는 보상 손실만으로 금지하지 않는다. 공격·회피 보조 보상은 에피소드 총합에 상한을 둬 전투만 반복하는 편법을 막는다. 실제 위협·명중을 원본 상태에서 구분할 수 없는 경우 해당 보상은 0으로 둔다.

## 저장과 재개

- `map_memory`: LMF 해시별 관측 칸, 마지막 관측 시각, 검증 전이. 동적 칸은 재관측 전까지 확정 경로로 쓰지 않는다.
- `physics_skills`: 지형/물리 맥락별 성공·실패와 원본 실행 증거. map_memory와 분리한다.
- `route_policy`와 `combat_policy`: 별도 체크포인트. `combat_mode=off`는 전투 정책을 호출하지 않는다.
- `opponent_tracker`: 미니맵/상대 상태의 최신 관측과 불확실성. 지도 기억과 분리해 오래된 상대 위치를 확정 사실로 취급하지 않는다.
- `manual_interventions`: 사용자의 조작과 직전 정체 상황을 별도 저장한다. 기본 정책에 자동 병합하지 않는다.
- 모든 체크포인트는 snapshot·LMF·관측 스키마·행동 스키마·물리 fingerprint를 기록한다. 불일치하면 조용히 이어 학습하지 않는다. 기존 공용 체크포인트는 자동 교체하지 않는다.
- CMD에는 현재 단계/맵/시도, view 크기, native 검증 수, 깃발 성공률, 평균 결정 수, 공격 모드, 수동 조작 여부, 체크포인트 경로를 짧게 표시한다. 중지 요청 시 현재 기록을 안전하게 저장한다.

## 사용자가 훈련할 때의 단계와 승격 기준

1. 물리 기술을 상황별로 학습한다. 각 기술은 보지 않은 위치·간격 변형에서 원본 x86 결과로 점검한다.
2. 전투 OFF로 발견 지도·국소 확장·깃발 탐색을 훈련한다. 학습에 쓴 맵/변형과 보지 않은 변형을 분리한다.
3. 미니맵의 멀리 있는 상대와 위에서 낙하하는 상대를 별도 상황으로 검증한다. 전투 PRIORITY에서는 실제 명중·회피가 확인되는 fixture에서 소량 보상을 학습한다. 깃발 성공률이 떨어지면 보상이나 전투 시간 상한을 조정한다.
4. 저장 경로 재생과 탐색기 도움을 끈 **독립 정책**을 기존 고정 후보·기존 DQN과 같은 원본 x86 기준으로 비교한다. 성공률, 결정 수, 리스폰, 시야 확장 횟수, 전투 보상 비율, 수동 개입 횟수를 보고한다. 수동 개입 없는 결과를 주지표로 둔다.
5. 새 후보가 보지 않은 변형에서 반복 성공하고 기존 성능을 해치지 않을 때만 기본 헬퍼로 승격한다. 오프라인 x86 성공은 일반 Client/온라인 성공이라고 표시하지 않는다.

## 현 코드와의 연결 상태

- `native_env.py`: 원본 x86 상태와 기존 입력 마스크. 현재 DQN 관측 9×9는 별도 스키마이며 이 설계의 가변 시야와 동일하지 않다.
- `discovered_map.py`: 실행 중 칸 기억과 native 전이 결과 기록의 기초. 디스크 재개, 동적 칸 유효기간, 물리 맥락별 전이는 아직 필요하다.
- `physics_first_planner.py` / `run_physics_first.py`: 제한된 수평 후보의 오프라인 검증기. 범용 재계획·학습기가 아니다.
- `watch_combat_ai.py`: 오프라인 전투 시연의 공격 스위치. 통합 깃발 헬퍼의 전투 정책은 아직 아니다.
- `COMBAT_NATIVE_PLAN.md`: 전투 원본 상태와 미확정 경계. 실제 피격·회피 출처 판정이 가능한 범위에서만 보상한다.
- `train_rule_helper.py`: 단일 맵·단일 플레이어 원본 x86에서 규칙 기반 이동과 상황별 행동값 저장을 담당한다. 범용 경로 계획, 온라인 직접 조작, 수동 개입, 미니맵 상대 추적, 전투 보상까지 구현됐다는 뜻은 아니다. 실행법은 `깃발헬퍼_훈련_사용법.md`를 따른다.
- `train_route_curriculum.py`: 훈1~20(중간 번호 포함) 맵별 실행을 조정하고 앞 맵의 상황별 행동값을 다음 맵으로 이식한다. 맵별 기록·중단·재개·최근 성공률 기준을 분리한다. 훈 기준을 통과한 뒤 혼1~20은 별도 실행기로 시작한다. 현재 훈련 성공률은 같은 맵 경험에서 나온 값이므로 독립 일반화 성적은 아니다.
